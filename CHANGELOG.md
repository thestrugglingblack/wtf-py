This project follows [Semantic Versioning](https://semver.org/) using the `MAJOR.MINOR.PATCH` format.

## [0.2.0] - 2026-09-08

### Added

* Added support for loading published WTF analytics datasets generated by the `wtf-data-platform` dbt analytics layer.

* Added `AnalyticsLoader` for reading published analytics Parquet datasets.

* Added `Analytics` class for convenient access to analytical datasets.

* Added support for the following analytics marts:

  * Player directory
  * Player game logs
  * Player season statistics
  * Quarterback season statistics
  * Player career statistics
  * Team season summaries

* Added analytics filtering by league and season where supported.

* Added helpers for discovering available leagues and seasons in analytical datasets.

* Added public analytics functions for:

  * `load_qb_season_stats()`
  * `load_player_career_stats()`
  * `load_team_season_summary()`
  * Analytical player game logs
  * Analytical player season statistics
  * Analytical player records

* Added analytics-specific dataset validation and missing-dataset error handling.

* Added centralized data-layer path resolution through `get_layer_path()`.

* Added release-root resolution to allow `wtfpy` to determine the location of related published data layers from the configured `WTF_DATA_PATH`.

* Added explicit support for resolving the following published data layers:

  * `canonical` → `<release>/datasets`
  * `analytics` → `<release>/analytics`

### Changed

* Expanded the public `wtfpy` API to support both canonical and analytical WTF data products.

* Updated package version from `0.1.0` to `0.2.0`.

* Preserved `WTF_DATA_PATH` as the single data-path configuration for both canonical and analytical datasets.

* `WTF_DATA_PATH` continues to point to the canonical published dataset directory:

  `<release>/datasets`

* Updated `wtfpy` to automatically resolve sibling analytics datasets from the same published release without requiring users to modify `WTF_DATA_PATH`.

* Centralized knowledge of the WTF release directory structure in `utils.py` instead of independently resolving paths inside individual loaders.

* Updated canonical dataset loading to resolve data through the centralized canonical data-layer path.

* Updated `AnalyticsLoader` to resolve analytics data through the centralized analytics data-layer path rather than calculating sibling paths directly.

* Canonical and analytics loaders now resolve against the same release:

  ```
  <release>/
  ├── datasets/
  │   ├── games.parquet
  │   ├── players.parquet
  │   └── ...
  └── analytics/
      ├── mart_players.parquet
      ├── mart_player_game_logs.parquet
      ├── mart_player_season_stats.parquet
      ├── mart_qb_season_stats.parquet
      ├── mart_player_career_stats.parquet
      └── mart_team_season_summary.parquet
  ```

* Kept canonical loading and analytical loading as separate package responsibilities:

  * `loaders.py` handles canonical WTF datasets.
  * `analytics.py` handles modeled and derived analytics datasets.
  * `utils.py` handles shared release and data-layer path resolution.

* Analytical metrics remain calculated by the upstream `wtf-data-platform` dbt models rather than being recalculated inside `wtfpy`.

### Configuration

A single `WTF_DATA_PATH` configuration now provides access to both canonical and analytical data.

For example:

```bash
export WTF_DATA_PATH="/path/to/wtf-data-platform/data/releases/v0.2.0/datasets"
```

Canonical loaders automatically resolve files from:

```text
<release>/datasets/
```

Analytics loaders automatically resolve files from:

```text
<release>/analytics/
```

Users no longer need to change `WTF_DATA_PATH` when switching between canonical and analytical datasets.

* Initial `wtfpy` project structure for working with women's tackle football data.

* Added Hatchling as the package build backend.

* Added development dependencies for:

  * pytest
  * pytest-cov
  * Ruff
  * mypy

* Added `src/`-based Python package layout.

* Established Python 3.11 as the minimum supported Python version.
